# Next Release

## Features

- **Gramps bridge (new component; addon only, C# client not yet started).** A Gramps-6.0 addon (`gramps-addon/MatrikelHelferBridge/`, Python, stdlib-only) serves a token-protected local HTTP/JSON API from inside the Gramps process so MatrikelHelfer can read the open family tree and write citations into it without any import/export cycle: `/ping` with tree/session info, endpoint-discovery file, person search (indexed, birth/baptism fallback dates, parents for disambiguation) and person detail (events with citation counts), source/repository lookup incl. dedup by `MH_SourceKey` attribute, and `POST /capture` — repository/source match-or-create, citation with structured date/confidence/attributes/notes, optional event creation, all in **one Gramps transaction** (single undo reverts everything) with `request_id` idempotency. Requirements doc: `docs/MatrikelHelfer-Gramps-Bridge-Anforderungen.md` (stage-0 write spike passed 2026-08-16, preserved in `spike/BridgeSpike/`). Verified by a **headless test suite** (26 integration tests over live HTTP inside the real Gramps runtime via `grampsd.exe` CLI, `gramps-addon\tests\run_tests.ps1`), plus manual checks per `gramps-addon/MatrikelHelferBridge/README.md`.

- Third provider: **ARCHION** (archion.de), the German Protestant church-book portal. Its citation metadata is login-gated (a server fetch without the browser's session returns a stripped page), so the extractor reads the **logged-in browser tab title** — which carries the full breadcrumb (Land / Archiv / … / Pfarrei / Buch with date range) — instead of fetching. Detected automatically from the URL. No image URL, archival signature, or sequential scan number (ARCHION exposes none); Seite stays manual. **Experimental:** when the viewer's Permalink panel is open, the exact-page permalink (`archion.de/p/…`) is read from the rendered page (UI Automation) and used as `{PageUrl}` — otherwise the page link falls back to the address-bar (book) URL. Model gained `PageUrl`/`EffectivePageUrl`; extractors now receive a `PageContext` (URL + tab title + on-demand page-link lookup).

- BibTeX in the first-start format seed: a **BibTeX** source format (a `@misc` bibliography entry) and a matching **BibTeX (\cite)** citation format. The cite key leads with the parish (human-recognizable in a `.tex` source) plus the signature.
- Template modifier `{Token:clean}`: turns a value into a key-safe identifier — transliterates umlauts (ä→ae), strips other accents, replaces runs of spaces/commas/periods with `_` (keeping hyphens like `3-01`), and renders an empty field as `EMPTY` so it stands out in the output. General-purpose (works on any placeholder); introduced for BibTeX cite keys.
- BibTeX-library export: an "@" button in the saved-entries panel writes a `.bib` file — one `@misc` entry per unique **book** (finds are deduplicated down to their books), rendered with your "BibTeX" source format, with cite keys made unique (`a`/`b`/`c` suffixes) so the file always compiles. If no "BibTeX" format exists, it offers to add the built-in one.
- Der BibTeX-Export kann jetzt an eine **vorhandene `.bib`-Datei anhängen**, statt sie nur neu zu schreiben — der realistische Fall, wenn die Bibliothek über Jahre wächst. Vorhandener Inhalt bleibt unangetastet (auch handgeschriebene Einträge und andere Quellenarten); ergänzt werden nur Bücher, die noch fehlen. Erkannt wird das am Link (`url`) und am Zitierschlüssel, wobei der Link Vorrang hat — umbenannte Schlüssel führen also nicht zu Dubletten. Neue Einträge weichen einem bereits belegten Schlüssel mit `a`/`b`/`c` aus.
- Jeder BibTeX-Export schreibt ein **Protokoll** (`Matrikelhelfer_Export.log`) neben die `.bib`-Datei: je Lauf ein datierter Abschnitt mit dem, was neu hinzukam, was bereits vorhanden war (und woran es erkannt wurde), welche Zitierschlüssel umbenannt werden mussten und welche Warnungen auftraten. In einer großen Bibliothek erspart das die Suche von Hand.

- Überarbeitetes Speichern von Funden. Bisher legte jeder Klick auf **Speichern** einen neuen Eintrag an, sobald sich irgendetwas am Datensatz unterschied — auch wenn sich nur die URL geändert hatte (`cHash`, `?pg=`, `/de/` statt `/en/`) oder nachträglich ein Zeichen im Kommentar ergänzt wurde. Dadurch sammelten sich viele Einträge für denselben Fund an. Neu: die Anzeige ist an einen gespeicherten Fund **gebunden** — weitere Änderungen aktualisieren ihn, statt einen zweiten anzulegen. Mehrere Funde auf derselben Seite bleiben ausdrücklich möglich (zwei Personen auf einer Seite); ein **geänderter Name** fragt nach (überschreiben oder neuer Eintrag), ein geänderter Kommentar nie. Die Rückfragen sind eigene Dialoge mit beschrifteten Schaltflächen („Überschreiben“ / „Neuer Eintrag“ / „Abbrechen“) — „Abbrechen“ bricht wirklich ab.
- Der Eintrag im Feld **Seite** gehört jetzt zur Kirchenbuchseite, nicht mehr zu jedem einzelnen Fund: Wird er korrigiert, gilt die Korrektur automatisch für alle Funde auf dieser Seite. Beim erneuten Lesen einer Seite wird die selbst eingetragene Seitennummer wieder angezeigt.
- Speicherformat auf `library.json` (Seiten + Funde) umgestellt. Ein vorhandenes `entries.json` wird beim ersten Start **automatisch übernommen** und anschließend als `entries-v1.bak` aufbewahrt (nicht gelöscht). Ist die Datei unlesbar, wird das Speichern gesperrt, statt sie zu überschreiben.

## Bug Fixes
- BibTeX-Export: Zwei Funde im selben DFG-Buch konnten als zwei verschiedene Bücher exportiert werden, wenn sich ihre URLs nur in Anzeigeparametern unterschieden (`id=9` vs. `tx_dlf[double]=0`). Die Buch-Identität wird jetzt normalisiert (Sprachsegment, Anzeigeparameter) — auch dieselbe Matricula-Seite auf `/de/` und `/en/` zählt als ein Buch.
- Matricula pages read on the English site (`/en/…`) left Buchtyp, Signatur and the dates empty — those fields are found by their German labels, which are English there (and the date *values* are localized too). The extractor now always reads the `/de/` version regardless of the browsing language (links still point to the page you opened).
